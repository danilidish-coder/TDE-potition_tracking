# Επιτόπια αποδοχή δοκιμαστικού EXE

Οι παρακάτω έλεγχοι **δεν έχουν εκτελεστεί** στο πραγματικό υπηρεσιακό περιβάλλον.
Αφορούν αποκλειστικά απομονωμένο test host, test share και πλασματικό προσωπικό.
Το CI δεν δίνει άδεια αντικατάστασης της παραγωγικής v1.2.5.

## Απομόνωση δοκιμών

- Αποσυμπιέστε το test artifact σε νέο φάκελο. Επαληθεύστε το EXE με
  `Get-FileHash .\TDE_Katagrafi_Theseon.exe -Algorithm SHA256` και το SHA256SUMS.txt.
- Χρησιμοποιήστε νέο SMB share, π.χ. `\\TEST-HOST\TDE_TEST`, χωρίς αντίγραφα
  πραγματικών υπηρεσιακών δεδομένων. Δημιουργήστε test roster XLSX με πλασματικά IDs.
- Σε κάθε PC ορίστε `TDE_POSITION_LOCAL_ROOT` σε νέο προσωπικό test profile και
  `TDE_POSITION_MACHINE_ROOT` σε **κοινό test φάκελο του ίδιου μηχανήματος**, π.χ.
  PUBLIC\Documents\TDE_TEST_Queue. Οι δύο Windows χρήστες του ίδιου PC πρέπει να
  βλέπουν την ίδια ουρά. Διαφορετικά PC χρειάζονται διαφορετική machine queue.
- Στο προσωπικό test profile δημιουργήστε μόνο test
  `position_tracking.settings.json`: central_root=test share, personnel_file=test
  XLSX. Για απλή απομονωμένη δοκιμή δηλώστε μη υπάρχον test shared_exe_path ώστε
  να μην ενεργοποιείται το bootstrap συντόμευσης. Το bootstrap έχει χωριστό έλεγχο.
- Εκκινήστε από shell με αυτές τις μεταβλητές μόνο για τη δοκιμαστική διεργασία.
  Μην ανοίξετε το test EXE με το υπάρχον παραγωγικό profile ή shortcut.
- Καταγράψτε Windows/build, DPI/ανάλυση, δύο test accounts, host/share ACL,
  EXE/commit SHA, ώρα και ζώνη ώρας κάθε PC. Μην αλλάξετε ώρα παραγωγικών PCs.

## Πίνακας υποχρεωτικών σεναρίων

| Σενάριο | Κριτήριο αποδοχής |
|---|---|
| 2+ clients διεκδικούν ταυτόχρονα την ίδια θέση/κατεύθυνση | Μία αποδεκτή κεντρική START, σαφές conflict/εκκρεμότητα στους άλλους, χωρίς overwrite |
| Πλήρης χρήση θέσεων 1–14, ιδιαίτερα ΕΞΟΔΟΣ | Σωστή αντιστοίχιση θέσης/κατεύθυνσης και ανεξάρτητα αρχικά START IDs |
| Host εκτός δικτύου πριν από START και END | Κάθε πράξη durable τοπικά, ορατή προσωρινή κατάσταση, καμία ψευδής κεντρική επιβεβαίωση |
| Επαναφορά host και πολλαπλό replay/restart | Ακριβώς μία εφαρμογή ανά αρχικό event ID, ίδια timestamps και END→START link |
| Διακοπή host στη μέση marker acknowledgement ή replay | Καμία απώλεια ιστορικού/ουράς, ασφαλής επανάληψη χωρίς διπλή δέσμευση |
| Windows account A→B στο ίδιο PC με pending END | Ίδια κοινή ουρά, προστασία αυθεντικού END timestamp/ID πριν από καθαρισμό προηγούμενου START |
| Lock και disconnect, έπειτα πραγματικό logoff/reboot | Lock/disconnect δεν συνεπάγεται αυθαίρετο END· ανάκτηση/hand-off σύμφωνα με τις πραγματικές συνεδρίες |
| NTFS/share ACL denied και επαναφορά | Καμία σιωπηρή προσωπική fallback ουρά, καμία διαγραφή/κρυφή μεταφορά pending δεδομένων |
| 09:59→10:00, 12/24ωρες και διαδοχικές βάρδιες | Σωστά χρονικά παράθυρα, pending/approved/excluded και αναίρεση αποδοχής/εξαίρεσης |
| Κλείσιμο ατομικών/ομαδικών θέσεων και stale START ID | Κλείνουν μόνο οι επιβεβαιωμένες τρέχουσες εγγραφές, χωρίς END σε νεότερη αντικατασταθείσα START |
| Ιστορικό, διορθώσεις ώρας και τελικές αναφορές | Συμφωνία events, SQLite sessions και παραγόμενων εγγράφων, χωρίς απώλεια αρχικών IDs |
| PDF/Word/Excel και πραγματικός εκτυπωτής | Ελληνικά/μορφοποίηση/σελιδοποίηση σωστά, αναμενόμενες διαδρομές και αρχεία |
| Ψυχρή εκκίνηση από το τοπικό bootstrap με host κλειστό | Επαληθευμένο τοπικό EXE, σωστή διαδρομή/ουρά και ασφαλής ενημέρωση επόμενης έκδοσης |
| Πολύωρη λειτουργία και κλείσιμο με μπλοκαρισμένο SMB I/O | Απόκριση χειριστή, ασφαλής καταγραφή και τεκμηριωμένος χρόνος εξόδου/ανάκτησης |
| Μικρή οθόνη/πολλαπλά monitors/high DPI και επαναλαμβανόμενα θέματα | Πρόσβαση σε όλα τα controls, ομοιόμορφη ζωγραφική και σωστή γεωμετρία |

Για κάθε σενάριο κρατήστε PASS/FAIL, ακριβή βήματα, αρχικά/τελικά event IDs και
ώρες, αντίγραφο μόνο του test dataset και screenshots/logs. Σε αποτυχία διατηρήστε
ολόκληρη την απομονωμένη ουρά και τα test receipts για διάγνωση. Η τελική απόφαση
παραγωγικής εγκατάστασης απαιτεί ολοκλήρωση αυτών των ελέγχων και ανθρώπινη έγκριση.

## Πρόσθετο πρωτόκολλο θωράκισης

- Καταγράψτε source/EXE SHA από το τελικό test artifact και το run URL. Οι
  μετρήσεις του συνθετικού soak αφορούν το GUI process, όχι ολόκληρο τον host.
- Επαναλάβετε με 15 πραγματικά PCs/clients στο test share. Μετρήστε στο κάθε
  PC GUI responsiveness, CPU, RSS και handles για τουλάχιστον 12/24 ώρες,
  με idle περιόδους και πραγματική εναλλαγή βαρδιών/χρηστών. Κρατήστε baseline
  μετά το warmup και καταγράψτε peaks/διαχρονική αύξηση, όχι μόνο τελική τιμή.
- Συλλέξτε `diagnostics/runtime-*.jsonl*` από το test `TDE_POSITION_LOCAL_ROOT`
  κάθε λογαριασμού. Με το κανονικό profile η βάση είναι
  `%LOCALAPPDATA%\TDE_Krystallopigis\PositionTracking`. Ο watchdog καταγράφει
  `gui_stall`, `gui_recovered`, `worker_stall`, `sample` και stacks χωρίς locals.
  Κρατήστε τα logs αμέσως μετά το περιστατικό πριν από μελλοντική rotation.
- Κατά την ελεγχόμενη διακοπή SMB δοκιμάστε ξεχωριστά ιστορικό/αναφορές,
  map διορθώσεις/λήξη, μηνύματα/ACK, έναρξη/μέλη βάρδιας και backup/audit.
  Παραμένουν ορισμένες συγχρονισμένες διαδρομές I/O. Απουσία προβλήματος σε
  απλό START/END δεν πιστοποιεί αυτά τα controls. Κάθε GUI stall είναι FAIL
  του αντίστοιχου σεναρίου και απαιτεί διάγνωση από τη συγκεκριμένη stack θέση.
- Δοκιμάστε κανονική και απομακρυσμένη έξοδο με pending offline START/END,
  διπλό αίτημα εξόδου και χαμένο ACK. Δεν επιτρέπεται κλείσιμο/ACK πριν από
  επιβεβαιωμένη λήξη ή απώλεια της τοπικής ουράς. Με προσωρινά μπλοκαρισμένο
  SMB η GUI πρέπει να συνεχίσει να ζωγραφίζεται και να δείχνει εκκρεμότητα.
  Καταγράψτε χωριστά GUI απόκριση και πραγματικό χρόνο τερματισμού process.
- Επιβεβαιώστε συγχρονισμό ρολογιών/NTP και timezone των test PCs. Σενάρια
  αλλαγής ώρας/DST απαιτούν απομονωμένες VMs· μην αλλάζετε ώρα υπηρεσιακών PCs.
- Ορίστε πολιτική διατήρησης διαγνωστικών ανά PC. Υπάρχει όριο rotation ανά
  process, αλλά τα logs παλιών συνεδριών διατηρούνται χωρίς αυτόματη διαγραφή.

Τα παραπάνω παραμένουν ΑΝΕΚΤΕΛΕΣΤΑ στο πραγματικό περιβάλλον.
