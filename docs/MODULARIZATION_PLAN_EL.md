# Σταδιακή απομόνωση modules — Καταγραφή Θέσεων v1.2.5

**Βάση:** επίσημο GitHub release `v1.2.5`, commit `33ea13ca2133ddbfb93b1d051d4b25dc35bd954f`. Δεν αντικαθιστούμε το υπηρεσιακό EXE.

## Κανόνες αποδοχής
1. Ένα μικρό module ανά αλλαγή, χωρίς μαζική μεταφορά 5.300 γραμμών.
2. Αποδεικνύουμε ότι η εξωτερική συμπεριφορά δεν άλλαξε, πριν προχωρήσουμε.
3. Κάθε module έχει δικά του αρνητικά/θετικά τεστ, σε Linux και Windows όπου ταιριάζει.
4. Εκτελούμε παλαιότερα regression και stress tests **πριν από την επόμενη ενότητα**.
5. Σε αποτυχία σταματάμε· δεν θεωρούμε τα μεμονωμένα PASS ως συνολική επιτυχία.
6. Η τελική κατασκευή χρειάζεται πραγματικό πολυτερματικό SMB/ACL field-test και εξωτερική έγκριση. Καμία αναβάθμιση παραγωγής αυτόματα.

## Διαπιστωμένο στο source v1.2.5
Η `_machine_queue_root()` επιλέγει `PUBLIC\Documents\TDE_Krystallopigis\PositionTracking_Queue`, **αλλά αν δεν μπορεί να γράψει κάνει σιωπηρή fallback σε per-user LocalAppData**. Αυτό μπορεί να κρύψει pending και να επανεμφανίσει παλιό αστυνομικό όταν αλλάζει ο Windows χρήστης. Δεν έχει αποδειχθεί ακόμη ως η μοναδική πραγματική αιτία. Η αποκατάσταση δεν θα γίνει με τυφλό κλείσιμο θέσεων ή απώλεια εκκρεμών εγγραφών.

## Κατάσταση σταδίου 1
Απομονώθηκε `src/position_tracking_windows_session.py` **με ακριβώς την παλιά συνάρτηση**, χωρίς αλλαγή λογικής. Η εφαρμογή εισάγει αυτή τη συνάρτηση από το module.
Νέο `tests/windows_session_module_regression.py` ελέγχει 10 WTS states, αποτυχία API και έναν μοναδικό ορισμό της συνάρτησης.
**Δεν υπάρχει νέα εγκεκριμένη παραγωγική έκδοση.**
