5. Σε αποτυχία σταματάμε· δεν θεωρούμε τα μεμονωμένα PASS ως συνολική επιτυχία.
6. Η τελική κατασκευή χρειάζεται πραγματικό πολυτερματικό SMB/ACL field-test και εξωτερική έγκριση. Καμία αναβάθμιση παραγωγής αυτόματα.

## Κατάσταση σταδίου 1
Απομονώθηκε `src/position_tracking_windows_session.py` **με ακριβώς την παλιά συνάρτηση**, χωρίς αλλαγή λογικής. Η εφαρμογή εισάγει αυτή τη συνάρτηση από το module.
Νέο `tests/windows_session_module_regression.py` ελέγχει 10 WTS states, αποτυχία API και έναν μοναδικό ορισμό της συνάρτησης.
**Δεν υπάρχει νέα εγκεκριμένη παραγωγική έκδοση.**

### Πραγματικό εύρημα από γενικό Windows regression (13/10/2026)
Το αρχικό full Windows CI απέτυχε στο παλαιό `tests/shift_smb_lock_concurrency.py` (PermissionError σε `os.write(fd, b"\\x00")` ΠΡΙΝ το `msvcrt.locking`). Συνεπώς το Stage 1 ΔΕΝ θεωρήθηκε πλήρως ολοκληρωμένο μόνο με το module test. Η προετοιμασία byte αφαιρέθηκε (Windows byte-range locks δεν χρειάζονται προεγγραφή) και προστέθηκε `tests/shared_file_lock_concurrency_regression.py` με 6 γύρους x 12 ταυτόχρονους χειριστές σε καινούρια lock files. Ο επανέλεγχος Windows απαιτείται πριν επιτραπεί το Stage 2.

### Στάδιο 2: Κοινή offline ουρά ανά υπολογιστή
Αφού ολοκληρώθηκε επιτυχώς το Stage 1 Windows module CI **και** το πλήρες Windows Build/GUI test (run 38450444433), μεταφέρθηκε η επιλογή path στο `src/position_tracking_machine_queue.py`. Δεν επιτρέπεται πλέον σιωπηρή χρήση `LOCALAPPDATA` σε Windows όταν `PUBLIC` δεν υπάρχει ή η κοινή ουρά δεν είναι εγγράψιμη. Μια παλιά προσωπική βάση με `PENDING` / `CONFLICT` εγγραφές μπλοκάρει νέες λειτουργίες και εμφανίζει εμφανές μήνυμα στην έναρξη, χωρίς διαγραφή, αναίρεση ώρας ή αυτόματη μεταφορά. Απομονωμένα regression ελέγχουν δύο διαφορετικούς Windows λογαριασμούς, περιπτώσεις ACL denied, εκκρεμή και corrupt legacy βάση και explicit κοινή διαδρομή. Ακολουθούν full tests και Windows GUI πριν από οποιαδήποτε επόμενη αλλαγή. Αυτό δεν αρκεί μόνο του για διόρθωση του προβλήματος "central old START blocks new user": εκείνο θα έχει ξεχωριστό handoff module με πλήρη προστασία event IDs και original timestamps.

### Στάδιο 3α — απομόνωση κεντρικού handoff χωρίς μεταβολή προηγούμενης συμπεριφοράς
Αφετηρία η πλήρως επιτυχής κορυφή b6015c6640955e5aeab84cc9b605272da3dc071d (Windows module run 38452237560 και Windows πλήρης/GUI run 38452237450). Το προηγούμενο `SharedEventStore.close_previous_windows_user_positions` μετακινήθηκε στο `src/position_tracking_handoff.py`, ενώ η αρχική δημόσια μέθοδος παρέμεινε thin wrapper. Προστέθηκε προαιρετικό `protected_start_ids` για αναγνωριστικά START που έχουν ήδη αξιόπιστο offline END, **ώστε να μην αλλοιωθούν τα αρχικά timestamps και event IDs** κατά τον μετέπειτα συγχρονισμό. Η συμπεριφορά της παλιάς κλήσης χωρίς προστατευμένα ID παραμένει ίδια. Νέο ανεξάρτητο `tests/windows_handoff_module_regression.py`: idempotence, μη λήξη σε ίδιο Windows χρήστη ή άλλο PC, στοχευμένη προστασία αρχικού event ID. Η αλλαγή σειράς synchronisation θα εξεταστεί **μόνο μετά από πλήρη επιτυχή Stage 3α CI**.

### Στάδιο 3β — διορθωμένη σειρά χειρισμού offline/central handoff (υπό πλήρη CI πιστοποίηση)
Το Stage 3α μεταφέρει αμετάβλητη την κεντρική συμπεριφορά στη χωριστή `position_tracking_handoff.py` και αναμένει επιτυχή module + full Windows CI πριν από το 3β. Το 3β αντιμετωπίζει τη διαπιστωμένη σειρά της παλιάς `_offline_tick`: ο συγχρονισμός τοπικού START γινόταν **πριν** από την κεντρική εκκαθάριση της προηγούμενης συνεδρίας Windows, ενώ ανεξάρτητος communication heartbeat μπορούσε να κλείσει το παλιό START **πριν** τον συγχρονισμό ενός ήδη εκκρεμούς END. Αυτή η σειρά οδηγεί σε αναπαραγώγιμο CONFLICT, κυρίως σε ΕΞΟΔΟ, ή σε απώλεια του αρχικού END timestamp.

Νέος κεντρικός συντονιστής `reconcile_handoff_before_replay`: (1) ταυτοποίηση μηχανήματος+Windows χρήστη, (2) προστασία ήδη υπαρχουσών CONFLICT, (3) ασφαλής εγγραφή λήξης προηγούμενου τοπικού χρήστη, (4) προστασία event IDs START που έχουν ήδη αυθεντικό END στην durable offline SQLite, (5) στοχευμένη κεντρική εκκαθάριση μόνο προηγούμενων λογαριασμών στο ίδιο μηχάνημα, (6) συγχρονισμός START/END στην αρχική σειρά με αρχικά IDs/timestamps. Αφαιρείται η ανεξάρτητη εγγραφή κεντρικής λήξης από το heartbeat thread ώστε να μην προπορεύεται του offline END. Σφάλματα τοπικής αρχικοποίησης handoff δεν αποκρύπτονται: εμφανίζεται λόγος και μπλοκάρονται νέες πράξεις ώσπου να επιβεβαιωθεί συμφωνία. Η προσωρινή απουσία κεντρικού δικτύου εξακολουθεί να διατηρεί offline εγγραφές χωρίς ψευδή επιβεβαίωση. Νέα tests: `tests/windows_handoff_replay_order_regression.py` (14 πραγματικές θέσεις, 7 ΕΞΟΔΟΣ, αλλαγή Windows χρήστη, αρχικό END timestamp/event_id, προηγούμενο START εκτός δικτύου, idempotence, αποτυχία SMB, ελλιπή ταυτότητα, ήδη υπάρχουσα ασυμφωνία). Η αλλαγή σειράς είναι **συνειδητή διορθωτική εξαίρεση** από τη συνήθη απαίτηση αμετάβλητης εξωτερικής συμπεριφοράς. Δεν εκδίδεται/δημοσιεύεται υπηρεσιακό EXE.
